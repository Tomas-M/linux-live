Unreleased changes
==================

Linux Live Kit
--------------

- Keep saved changes marked active until their backing filesystem is ready to
  unmount, and restore the marker if the final unmount fails. Report failed
  unmounts and continue shutdown without prompting for input.
- Check native FAT, exFAT and ext2/3/4 recovery flags before boot mounts. Use RAM
  and report suspect storage or a failed saved-changes mount for offline repair.
- Keep generated NTFS mounts read-only when the hibernation-checking automounter
  is unavailable.
- Expose required boot and saved-changes mounts under /media even with
  noautomount, while leaving other filesystems unmounted.
- Increase the generated fstab device timeout from 10 to 30 seconds.
- Mark active saved changes durably and continue in RAM after an interrupted
  shutdown without waiting for boot-menu input. Retain the interrupted device,
  filesystem identity and changes path for desktop recovery. Copy an affected
  boot source to RAM when memory allows so its filesystem can be checked offline.
- Link every available BusyBox applet in initramfs, including strings, using
  the complete applet list instead of parsing formatted help output.
- Include common vendor HID keyboard drivers and Apple SPI keyboards with their
  controllers in initramfs so they are available for early boot menus.
- Skip EFI System Partitions during live-data discovery, storage selection and automount.
- Update the static initramfs blkid and eject to util-linux 2.42.4 and Mini Commander to 2.0.
- Show device search results, mount errors and storage messages when live data
  cannot be found, with a complete diagnostic report retained in RAM.
- Automatically size persistence containers from their backing filesystem and grow
  existing containers without shrinking them; remove the perchsize boot parameter.
- Update DynFileFS to 6.03 with incremental checkpoints and automatic format-500 conversion.
- Safely publish DynFileFS metadata and saving-policy updates, and wait for persistent
  storage and its backing filesystem to finish closing before powering off.
- Report reusable capacity released by deleting individual DynFileFS saved states,
  using cached block ownership instead of scanning saved filesystem contents.
- Allow disabling DynFileFS automatic end-of-run points without disabling explicit
  saved states or normal filesystem synchronization.
- Rename DynFileFS saved states by stable identity while retaining their data,
  ancestry, open read-only views and restore targets. Expose saved images by ID.
- Keep DynFileFS backing files and automatic filesystem freezing accessible after
  switching from the initramfs to the live root, fixing persistent boot I/O errors.
- Restore a saved state at storage startup using its stable ID; keep the
  request on failure and stop for recovery instead of silently continuing in RAM.
- Keep one DynFileFS changes.dat directly in changes on every filesystem,
  including native Linux storage; ignore older numbered profile directories.
- Choose a drive and then a saved state during boot. Fresh start restores
  Initial state while retaining history; F5 refreshes the drive list.
- Preserve the starting state before persistent writes and apply save/discard
  policy at the next activation; protect restore targets during recovery.
  Recover interrupted creation of the starting state without losing unrelated points.
- Reuse an identical saved state before restoring instead of duplicating it;
  promote matching automatic points and suppress intermediate restore snapshots.
  Name newly retained states after the restore target, without repeated timestamps.
- Give new containers a permanent Initial state saved state after
  formatting and filesystem growth; hide the unusable pre-formatting point.
- Show saved-state branches in the boot picker using DynFileFS's ordered tree rows.
  Keep menu navigation at the first or last row instead of wrapping around.

Slax
----

- Keep automatically generated Xorg fallback settings in RAM for one startup
  attempt, and discard previously saved autodetection files before desktop startup.
- Continue opening a repaired drive in the requesting File Manager window or GTK
  dialog, without overriding a newer selection. Cancel and failed checks keep
  the unavailable target empty. Open automount windows only for newly attached
  devices or real media changes, preserving ordinary hotplug behavior.
- Offer filesystem checking from blocked drive rows in File Manager and native
  GTK file dialogs, sharing Slax Status's confirmation, repair backend and live
  report. Check ordinary unmounted drives without interrupting saved changes.
- Preserve the complete window frame during close animations instead of
  clearing its title before the rest of the window fades.
- Check NTFS hibernation during startup automount. Show drives that need checking
  in PCManFM and GTK file dialogs, and offer manual mounting after repair.
- Select sidebar locations immediately in PCManFM and GTK file dialogs. Clear
  the file pane and path for unavailable targets, retain their selection after
  failed mounting, and avoid selection changes during catalogue refreshes.
  Ignore late mount results after another location has been chosen.
- Show why a filesystem needs checking in Slax Status, replay recoverable XFS
  logs and verify writes and unmount before offering a restart after repair.
- Replace generated file-manager bookmarks with native Home, File System,
  device and shared-folder rows. Discover unmounted filesystems independently
  of automount, including VirtualBox shares, and support manual mount/unmount

  icons, spacing, circular controls and continuous hover highlight.
  Highlight file captions on hover; hide file and sidebar item tooltips while

  Give 24 px device icons dedicated artwork with one-pixel blue drive/USB outlines

  Keep mount/unmount feedback readable and preserve the current row selection
