SLAX USER KNOWLEDGE
Scope: Slax 2026.11, Debian 13 (trixie), 64-bit x86; shipped defaults.
Prefer graphical instructions for desktop users. Users can customize defaults;
check the running system when needed. Older Slax guides may describe other versions.

DESKTOP
- Fluxbox manages windows and four workspaces. PCManFM supplies desktop icons,
  wallpaper and File Manager. The bottom panel uses Xfce components.
- Open the launcher: click the bottom-left Slax button, tap Super (Windows key),
  or press Alt+F2 / Ctrl+Esc. Type to search apps or run a command; browse categories
  with the sidebar. Esc dismisses it.
- Click a taskbar icon to select its application; hover for window previews and
  click a preview to activate it. Alt+Tab switches windows; Alt+Shift+Tab reverses.
  Alt+F3 opens the window overview. The taskbar normally shows the current workspace.
- Click the workspace pager near the clock to switch workspace.
- Click the speaker icon in the taskbar to open the volume slider and mute toggle.
  Scroll over the icon to adjust volume.
- On computers with a system battery, hover over the battery icon in the tray to
  see its charge and status.
- Click EN (or the current layout label) in the taskbar to select a keyboard layout.
  Ctrl+Shift, Alt+Shift and Super+Space switch layouts when the keys are released.
- To reorder tray icons, run xfce4-panel --preferences, open Items, select Status
  Tray Plugin and open its settings. In Systray Icons, select an item and use the
  up/down arrows.
  Status Notifiers has a separate list for applications using that tray protocol.
- Close a tray bubble with Esc or by clicking another window.
- Slax Status starts with the desktop. Click its stacked-drive tray icon to see
  where Slax runs, where changes are stored and the estimated space available.
  The number shows available space; the bar shows how much is used.
  Drives are identified by /dev/device, followed by their label in parentheses.
  Available space includes reusable blocks already allocated inside the active container.
  Low-space and storage warnings appear beside the icon;
  Remind in 15 min postpones them. Open Saved states from this bubble.
- Right-click empty desktop space for Create New and Desktop Preferences.
  Desktop Preferences controls wallpaper, icon appearance and screen resolution.
  After a resolution change, choose Keep changes within 10 seconds; Revert or
  the timeout restores the previous mode.
- Drag title bars to move windows and borders/corners to resize them. Double-click
  a title bar to maximize/restore; right-click it for window options.
- Launcher > Session provides Logout, Restart and Shut down. Logout ends the
  graphical session. Restart/Shut down act immediately: save open work first.

FILES AND DRIVES
- Open File Manager from the launcher. Double-click files/folders to open them.
  The sidebar shows Home Folder, File System (/), available drives, shared folders
  and personal bookmarks. Ctrl+L focuses
  the editable path bar; enter a path and press Enter or click Go.
- Save the current folder with Bookmarks > Add to Bookmarks. Personal bookmarks
  appear under Bookmarks between Places and Devices; the section appears only
  when it contains bookmarks. Right-click a bookmark to rename or remove it.
- Native GTK 3 Open and Save dialogs use the same available drives, shared folders
  and personal bookmarks as File Manager. Mount or unmount a filesystem directly
  from their sidebar, including when Slax starts with noautomount. Use the path
  field or Ctrl+L to enter a folder or file path; Back, Forward, History and Up
  navigate within the dialog. Alt+Left, Alt+Right and Alt+Up are the shortcuts.
- Click a drive marked Check required in File Manager or a native GTK file
  dialog to review and confirm a filesystem check. Both use Slax Status's
  checker and live report. Ordinary drives stay unmounted during checking.
  A successful check continues opening the drive in the original window or
  dialog if it is still selected. NTFS repairs require Windows.
  If NTFS hibernation cannot be ruled out, Slax keeps that drive read-only.
  Automount can open a window for a newly attached drive or inserted medium;
  checking or refreshing an existing drive does not open another window.
- A sidebar click selects that location immediately. If it cannot be opened or
  mounted, its selection stays and the file pane and path are empty. Choose
  another location or use Back to return to the previous working folder.
- Toolbar: Back, Forward, History, Up. Right-click files or empty space for actions
  such as Create New, Rename and Properties. Ctrl+C/Ctrl+V copies, Ctrl+X/Ctrl+V
  moves, Ctrl+H toggles hidden files, F2 renames the selection.
- Delete permanently removes files after confirmation with the default settings.
- Each desktop uses its own Desktop, Documents, Downloads, Music, Pictures,
  Public, Templates and Videos folders: /root for root, /home/guest for guest.
  Chromium launched from root runs as guest with a separate browser profile and
  saves downloads to /root/Downloads by default. Chromium in the guest desktop
  uses /home/guest/Downloads. Other standard document folders follow the same rule.
- Available filesystems appear in File Manager even with noautomount. Click an
  unmounted entry to mount and open it, or its circular + button to mount it without
  changing folders. The circular unmount button disconnects an ordinary mounted
  filesystem; the entry remains available for mounting again. A busy filesystem
  stays mounted until its files and terminals are closed. Unmounting the current
  folder returns to Home Folder.
  With automount enabled, attached filesystems mount under /media, normally
  /media/DEVICE (e.g. /media/sdb1). Boot and saved-changes storage show a lock
  while Slax uses them. VirtualBox shares are offered even when unmounted;
  manual unmounting prevents their automatic remount for the rest of this boot.
  EFI System Partitions are skipped by automatic mounting and by boot/profile discovery.
  The installer reserves them for EFI boot files; choose a separate data partition for Slax.
- Right-click a local .iso > Mount to browse it read-only under /media/ISO-...;
  its sidebar entry has an unmount button.
- Print Screen (fbprintscreen) saves a screenshot in ~/Pictures and opens a viewer.

NETWORK, AUDIO AND KEYBOARD
- Open Net Manager from the launcher or network tray icon to select wired/Wi-Fi
  connections and enter credentials. ConnMan provides networking and time sync;
  connmanctl is its command-line interface.
- By default, the SSH server does not start automatically. To enable it for this run,
  use systemctl start ssh as root.
- Moving the volume slider unmutes; mute remembers the selected level.
  Right-click the speaker icon for additional audio settings.
- In the keyboard menu, Show all lists additional available direct-input layouts
  alphabetically.
- Layout shortcuts initially cycle the main flagged layouts. Picking a non-English
  layout in the menu, or using it continuously for 30 seconds, remembers it as the
  alternate; shortcuts then toggle English and that alternate. A new menu selection
  replaces it. The active layout and alternate are restored on login in a persistent
  profile.
- VirtualBox, VMware and QEMU/KVM with SPICE have clipboard/resize integration;
  enable corresponding host integration. Host shares: VirtualBox /media/sf_*,
  VMware /mnt/hgfs.

  Alt+F3               Window overview.
  Alt+Tab              Next window; add Shift for previous.
  Alt+F4 / Alt+F9      Close / minimize window.
  Alt+F10 / Alt+F11    Maximize / fullscreen window.
  Alt+Space            Window menu.
  Alt+left/right drag Move/resize from inside a window.
  Ctrl+Alt+Left/Right Previous/next workspace.
  Ctrl+F1..F4          Select workspace 1..4.
  Super+Left/Right    Send window to previous/next workspace.
  Ctrl+Super+Left/Right Send window and follow it.
  Print                Screenshot.
Ctrl+drag a title bar onto another window to group them as Fluxbox tabs;
Super+Tab switches grouped tabs. These differ from File Manager's own tabs.

APPLICATIONS AND PACKAGES
- Included: Web Browser (Chromium), File Manager (PCManFM), Terminal (xterm),
  Text Editor (SciTE), Calculator (galculator), X Archiver, Net Manager,
  Partition Manager, Slax Installer and Slax Assistant.
- Click-to-install entries: Drawing, Video Player (VLC), Remote Desktop (Remmina),
  Task Manager (LXTask), Document Scanner (Simple Scan), CD/DVD Burner (Xfburn),
  Mines and Sudoku. Click normally: fbinstall downloads the required packages
  and launches the app. Subsequent launches open it directly. First use needs
  internet; persistent profiles retain installed applications.
- Debian APT manages software: apt-get update; apt-get install PACKAGE.
  Search with apt-cache search TERM. The default desktop/terminal run as root,
  so no sudo prefix is needed. apt-mark showhold lists the kernel and customized
  desktop packages held to preserve matching Slax boot files and desktop behavior.
- Terminal package installation can show text configuration dialogs. Use Tab,
  arrow keys and Enter to choose and confirm answers.
- Launch Chromium through Web Browser or fbliveapp chromium; it runs as guest
  with its browser sandbox. Video Player also runs as guest.
- Slax Assistant is installed but does not start automatically. It does not run
  or perform any tasks until the user launches it. Open Slax Assistant from the
  launcher (slax-ai); this starts linux-assistant and opens its local interface
  in a dedicated browser app.
- Run linux-assistant --cli for a terminal-only interface in a text console,
  including when the desktop cannot start, to help diagnose and fix the problem.
  Both interfaces require internet access. If Wi-Fi or another connection is
  broken, temporarily connect through another route, such as Ethernet or USB
  tethering from a phone, then ask the assistant to fix the original problem.

BOOT AND PERSISTENCE
- Slax boots from CD/DVD, USB or an installed disk through BIOS or UEFI. Debian's
  signed UEFI chain supports Secure Boot. Esc during the five-second countdown
  reveals the full boot menu.
- Slax detects graphics hardware at each startup. If automatic desktop startup
  fails, it tries a basic framebuffer display when available; this may limit
  screen resolution. This fallback is not remembered across boots.
- Slax keeps saved changes and saved states together on the selected drive.
  Each drive has one history; there are no separate profiles or sessions to manage.
- Normal startup continues saved changes from the most recently selected writable
  drive. On a writable boot medium, storage can be prepared automatically.
- Choose a saved state opens a drive list, then that drive's saved-state tree. Choose
  Last saved state to continue, a saved state to return to it, or Fresh start
  to return to the original Slax. Fresh start keeps the existing history.
  On a drive without saved changes, Fresh start prepares storage there.
  F5 Refresh detects newly connected disks in the drive list. Esc from history
  returns to drives; Esc from drives continues in RAM without saving changes.
  Last saved state respects the previous run's Keep changes after restart choice.
- Run Slax from RAM (with no automount) copies the complete Slax source into memory,
  allowing removal of the original medium. This entry keeps system changes in RAM;
  save files to a mounted drive to retain them after shutdown. This entry leaves
  automatic disk mounting disabled. Slax Status does not mount other drives.
- Start Slax in text mode only (no desktop) opens a console session. Run startx
  from a logged-in console to start the graphical desktop.
  The guest account starts the same Slax desktop, with its own
  settings and files. Restart and Shut down work for the active local guest
  session. Slax Status also works as guest; other administrative tasks require root.
  Text mode retains nomodeset for emergency graphics; when only a firmware
  framebuffer is available, startx uses it and the resolution may be fixed.
- If saved changes were not closed properly, their filesystem needs checking,
  or Slax cannot mount their drive, changes may start in RAM. Slax Status names
  the affected device and explains why it needs attention. Choose
  Check and repair, close files using that drive, then confirm. Slax unmounts
  the filesystem, repairs it and verifies that it mounts and unmounts cleanly.
  After a successful check, mount the drive in File Manager or choose Restart
  to resume its saved changes.
  Changes made in this RAM run stay in RAM.
  Failed checks leave saved changes blocked. A window shows live checker output
  and scrolls as it arrives; the full report is at /run/slax-status/fsck.log.
  Automatic repair supports FAT, exFAT, ext2/3/4 and XFS. Btrfs starts with a
  read-only check. Review errors before choosing Attempt Btrfs repair: repair
  requires a separate confirmation and can cause unrecoverable data loss.
  All Btrfs member devices must be connected and available for offline checking.
  NTFS must be checked and repaired in Windows with drive error checking or chkdsk.
  After a successful manual check, mount the drive and run, as root,
  /run/initramfs/persistence enable /media/DEVICE/slax/changes before restarting,
  replacing the directory with the actual saved-changes location.
  If the affected drive also contains Slax, boot copies its source to RAM when
  enough memory is available. If it cannot read the live files or cannot release
  the drive, start Slax from another medium to check the affected drive.
- Saved changes use slax/changes/changes.dat directly on the selected drive,
  including on Linux filesystems. DynFileFS grows its data parts as needed;
  all files beside changes.dat and its snapshots directory belong together.
  Back up the complete changes directory while inactive, after a normal shutdown.
  Old numbered directories from earlier Slax versions are left alone and ignored.
- Open Saved states from the Slax Status tray bubble to manage the history
  on the currently used drive. Current session and You are here identify this run.
  Show removed states in the bottom bar includes deleted states.
  Go to now selects and reveals Current session.
  The separate Current session section at the bottom right controls whether this
  run’s changes are kept after restart, regardless of the selected saved state.
  Sizes beside deletable states show space reusable for new changes after deletion.
  These sizes are not additive: deleting several states can free more space than
  their individual sizes suggest. The storage files reuse space rather than shrinking.
  In a RAM run, this window offers mounted drives. Select a writable drive and
  Enable and restart to start saving changes from the next Slax run. Future runs
  can keep apps, settings and files and create saved states. The current RAM run
  cannot be saved or transferred; copy important files to a drive before restarting.
  A drive or saved state selected at boot also selects that drive for future
  automatic resume. Resume continues its latest kept changes rather than
  repeatedly restoring the originally selected saved state.
- Save a named state saves the current apps, settings and saved files under a name
  so you can return to them after making more changes. Restore asks for confirmation
  and restarts Slax into the selected saved state. Save open documents first.
  The confirmation's Keep changes after restart switch chooses whether to keep installed
  programs, settings and saved files as another saved state or discard this run's changes.
  Saved states do not remember open program windows or unsaved work.
  Close applications using saved-state files before restoring.
  If restarting fails, the restore request is cancelled; the switch retains
  the choice confirmed in the dialog.
  Rename gives a saved state a new name. Naming an automatic state keeps it until
  explicitly deleted. Initial state cannot be renamed.
  DynFileFS also creates automatic states at storage startup and clean shutdown
  when the state changed. History labels them Saved on restart.
  Slax keeps four recent automatic states; states still
  in use may be kept longer.
  Named states remain until explicitly deleted. Normal startup continues the
  saved current state unless a restore or discard was requested.
  Before restoring with saving enabled, Slax retains the recovered previous state
  as Before restoring <target name>. An identical existing state is reused;
  automatic states become permanent, and manually named states keep their names.
  This restore does not add an intermediate automatic state.
  With Keep changes after restart turned off, it does not retain that run
  as an automatic state. Existing saved history stays available.
  Fresh start at boot and restoring Initial state return to the original Slax
  while keeping existing saved states.
- Open files opens a saved state's complete filesystem root read-only in File
  Manager. Copy files out before closing it. The view disconnects automatically
  after its last File Manager window closes. If another application is still
  using the files, disconnection waits until it releases them. A state needing
  filesystem recovery can be used at next start.
- Keep changes after restart controls the active store. Turning it off returns
  to this run’s starting state on the next activation; an explicit restore selection takes
  precedence. A manually saved state remains available even when this switch is off.
  Turning it off also prevents an automatically saved state for the discarded run.
  RAM runs cannot keep changes after restart.
- Files saved directly to mounted drives remain independently of saved Slax changes.
  savechanges exports changes as a module; ordinary persistence saves automatically.

INSTALLATION AND DISKS
- Open Slax Installer or run slax-install-linux. Media paths:
  /slax/installer/slax-install-linux on Linux; slax-install.exe beside it on Windows.
- Linux installer requirements: glibc 2.27 or newer, GTK 3.22 or newer, libudev,
  libblkid and liblzma5.
- Wizard: Welcome > Slax source > Target drive > Installation > Finish.
  Browse selects an ISO or Slax directory (a parent containing slax also works).
  The running source can be detected, including copy-to-RAM. Choose a target,
  press Next, review the plan and approve the installation.
- Erase unchecked preserves unrelated files and existing systems. Updating an
  existing slax directory replaces matching source files, retaining unmatched
  files and the complete slax/changes tree.
- Erase entire selected disk affects ALL its partitions, including hidden ones;
  check the disk and sibling list in the confirmation. Eligible target partitions
  are larger than 1 GB. Boot options depend on the actual layout. After completion,
  reboot and select the target drive in the computer's boot menu.
- Partition Manager edits partition layouts/filesystems: Add to plan > Review
  changes > Apply changes. Slax Installer copies Slax and prepares booting.
- A USB made by directly writing the ISO has separate instructions on USB-SPACE.
  On Windows, usb-space.exe (Use USB Space) makes unused capacity into USB-DATA.
  In Slax: Partition Manager > Repair layout if offered > create FAT32 in
  Unallocated space > review/apply. The Slax installation is retained.

MODULES AND CUSTOMIZATION
- .sb files are compressed SquashFS filesystem modules. The shipped layers are
  01-core, 02-firmware, 03-desktop and 04-chromium. Add compatible modules under
  the boot source's slax/modules and reboot. Higher-numbered layers override
  lower-numbered layers; persistent changes provide the writable layer above them.
- slax/rootcopy mirrors absolute paths: rootcopy/etc/example.conf is copied to
  /etc/example.conf at boot. Retain required permissions and ownership.
- Source locations: /run/initramfs/memory/data/slax, .../iso/slax or .../toram
  (all under /run/initramfs/memory). Use a writable source or recreate an ISO
  to distribute extra modules/rootcopy files.

SLAX-SPECIFIC COMMANDS
Filesystem/module commands run as root; quote paths containing spaces.
  slax list
    Show loaded modules and source files.
  savechanges /path/99-custom.sb [changes_directory]
    Export changed files to a module, filtering caches/logs/runtime files.
    Choose a new file on a writable drive. Without arguments, writes
    99-changes-N.sb into the boot data's modules folder; saves in the same boot
    reuse that filename.
  mkdir /tmp/edit.sb; sb2dir module.sb /tmp/edit.sb
    Extract into an existing directory, keeping the original module.
  dir2sb /tmp/edit.sb /path/99-custom.sb
    Pack into a new module. Sources ending in .sb or named squashfs-root contribute
    their contents; other source names include the directory itself.
  sb FILE_OR_DIRECTORY [output]
    Conversion wrapper. Without an output, sb FILE.sb replaces the module with
    a RAM-backed editable directory; run the same command again to repack it.
    For an input named exactly initrfs.img, sb initrfs.img unpacks the XZ initramfs
    into a RAM-backed directory; run it again to repack the image in place.
    Initramfs mode ignores [output]; other image names need the direct helpers below.
    rmsbdir FILE.sb (or sb rm FILE.sb / sb rmdir FILE.sb) discards that tree.
  genslaxiso [-e exclude_regex] [-r rootcopy_dir] target.iso [module.sb ...]
    Recreate a BIOS/UEFI ISO from the boot source; add supplied modules and
    optionally replace rootcopy. Saved profiles are excluded. Example:
    genslaxiso -r /path/rootcopy /media/DRIVE/custom.iso /path/99-custom.sb
  fbappselect / fbprintscreen / fblogout
    Open launcher / take screenshot / open session actions.
  fbsetkb us / fbsetkb cz
    Select US English / Czech through the running keyboard tray.
  fbliveapp COMMAND [ARGS...]
    Run an app as guest from the root desktop with its own D-Bus session.
  fbstartupnotify COMMAND [ARGS...]
    Launch a command with desktop startup feedback.
Advanced: pxe [INTERFACE] serves Slax over DHCP/TFTP/HTTP to BIOS/UEFI clients;
UEFI clients use the bundled signed shim and network GRUB, supporting Secure Boot.
Use a network where starting DHCP is intended. initramfs_unpack initrfs.img and
initramfs_pack initrfs.img edit/repack that image in place. slax activate FILE.sb
and slax deactivate FILE.sb require AUFS; the current OverlayFS build loads
added modules at the next boot instead.

QUICK DIAGNOSTICS AND SETTINGS
- If boot stops with "Could not locate slax data", photograph the diagnostic
  screen. It shows the preferred filesystem, device search results and storage
  errors.
  In the recovery shell, more /var/log/live-data.log opens the complete report;
  this report is in RAM and disappears after reboot.
- System: cat /etc/slax-version; uname -r; cat /proc/cmdline.
- Disks/space: lsblk -f; findmnt /; df -h. Boot logs: /var/log/boot.log,
  journalctl -b. Network: ip addr; ip route; connmanctl services; rfkill list.
  Audio devices: aplay -l. Terminal tools include htop and Midnight Commander (mc).
- timedatectl set-timezone REGION/CITY changes timezone (default UTC).
- Saved keyboard: ~/.config/slax/keyboard (or $XDG_CONFIG_HOME/slax/keyboard);
  window shortcuts: ~/.fluxbox/keys; launcher appearance: /etc/xlunch/focus.ini.
- tmux prefix is Ctrl+A: then | splits left/right, _ splits top/bottom;
  Alt+Arrow selects panes. Mouse support is enabled.
